# Clients Implementation Plan (Rust, Python, TypeScript)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development with the project skill `uf-workflow` and the agents in `.claude/agents/`. This plan runs in its own git worktree, in parallel with gateway plan 4's last tasks; it touches no gateway or console file.

**Goal:** One client surface — chat, streaming chat and embeddings — in Rust, Python and TypeScript, against the gateway or a provider directly, built on the `translate` crate so every language shares one implementation of the formats.

**Architecture:** `crates/client` is a Rust library on `translate` + reqwest: a `Client` with a target (gateway or provider kind + base URL + key), `chat`, `chat_stream`, `embed`; typed errors with `retryable`. `crates/client-py` wraps it with PyO3 (abi3, sync and async classes; streams as Python iterators/async iterators) built by maturin. `crates/client-wasm` compiles `translate` (no I/O) to WebAssembly with wasm-bindgen; `clients/ts` is the npm package that does networking with the runtime's `fetch` and calls the wasm for request building, response and SSE parsing. The owner has decided this architecture (memory: client architecture) — do not propose alternatives.

**Tech Stack:** Rust 1.94, reqwest 0.13 (rustls), PyO3 + maturin (abi3-py39), wasm-bindgen (+ wasm-pack or `wasm-bindgen-cli`), TypeScript (ES2022, no runtime deps), Vitest for TS, pytest for Python.

**Spec:** `docs/superpowers/specs/2026-09-28-gateway-v2-design.md` section 14 (and 5 for `translate`). Conventions: `docs/CONVENTIONS.md`.

## Global Constraints

- Same surface everywhere: `chat(request) -> response`, `chat_stream(request) -> stream of events`, `embed(request) -> embeddings`; request/response types mirror `translate::types` (text-only messages, max_tokens, temperature, top_p, stop; usage; finish_reason).
- Targets: `gateway(base_url, key)` (OpenAI wire format against `/v1`), or a provider directly: `openai(base_url?, key)`, `anthropic(key)`, `gemini(key)`, `azure(endpoint, deployment-as-model, key, api_version?)`, `openai_compatible(base_url, key)` — exactly the provider kinds `translate` supports.
- Clients do not retry, route, cache or break circuits. Every error is typed with `kind` (auth | permission | not_found | invalid_request | rate_limited | upstream | network | timeout | malformed) and `retryable: bool` (true for rate_limited, upstream 5xx, network, timeout) and `retry_after` seconds when the server sent one.
- Gateway tags: `tags: {string: string}` on a request, sent as header `x-uf-tags` (JSON, ≤ 1 KiB) only to a gateway target; never to providers. (The gateway stores tags in a later plan; until then it ignores the header.)
- Keys are never logged, never in error messages, never in `Debug`/`repr`/`toString`.
- `translate` stays sans-I/O and must compile for `wasm32-unknown-unknown`; any change to it keeps every existing gateway test green.
- Toolchain installs are user-level only (rustup target, cargo install, pip --user/uv); no sudo. If something needs sudo, report it.
- Production safety per CONVENTIONS (never touch the service on :3900). Tests use mock servers on free ports.

## Review Focus

1. A stream that ends with an error event after some text → the caller gets the text events, then a typed error; no silent truncation. (Task 1, 3, 4)
2. A provider 429 with Retry-After → `rate_limited`, `retryable=true`, `retry_after` set — in all three languages. (Task 1, 3, 4)
3. The API key never appears in any error, log or repr, including on connection failures (reqwest errors carry URLs, not headers — still assert). (Task 1, 3, 4)
4. Tags are sent to a gateway target and never to a provider target. (Task 1, 3, 4)
5. The TS package works without Node-specific APIs (no `Buffer`, `process`, `fs`) so it runs in browsers and edge runtimes; streaming uses `ReadableStream` + `TextDecoder`. (Task 4)

### Task 1: Rust client (`crates/client`)

**Files:** Create `crates/client/{Cargo.toml,src/lib.rs,src/target.rs,src/error.rs,src/stream.rs}`, `crates/client/tests/{chat.rs,stream.rs,embed.rs,errors.rs}`, `crates/client/README.md`; Modify root `Cargo.toml` (workspace member).

**Interfaces:** `pub struct Client` (`Client::new(Target) -> Client`, `.with_timeout(Duration)`, `.with_http(reqwest::Client)`); `pub enum Target { Gateway{base_url, key}, Provider{kind: ProviderKind, base_url, key, api_version: Option<String>} }` with constructors `Target::gateway`, `::openai`, `::anthropic`, `::gemini`, `::azure`, `::openai_compatible`; `async fn chat(&self, ChatRequest) -> Result<ChatResponse, Error>`; `async fn chat_stream(&self, ChatRequest) -> Result<impl Stream<Item = Result<StreamEvent, Error>>, Error>`; `async fn embed(&self, EmbeddingsRequest) -> Result<EmbeddingsResponse, Error>`; `ChatRequest` builder helpers (`ChatRequest::new(model).user("…").system("…")`); `Error { kind: ErrorKind, message, status: Option<u16>, retryable: bool, retry_after: Option<Duration> }` (`Display` without the key). Re-export `translate::types`.

**Rules:** gateway target uses the OpenAI ingress format against `{base}/v1/chat/completions` and `/v1/embeddings` with `Authorization: Bearer`; provider targets use `translate::provider::build_request` / `parse_response` / `StreamDecoder` exactly as the gateway does. Tags header on gateway only. Errors map from HTTP status + `TranslateError` + reqwest errors.

**Tests:** wiremock (or a tiny hyper server) for every target kind: chat, stream (incl. split at every byte for one stream), embed; Review Focus 1–4; a key-leak test that formats every error variant with Display and Debug and searches for the key.

- [ ] Tests RED → implement → gates (fmt, clippy, `cargo test -p ultrafast-client`) → commit.

### Task 2: `translate` for WebAssembly (`crates/client-wasm`)

**Files:** Create `crates/client-wasm/{Cargo.toml,src/lib.rs}`; Modify `translate` only if needed for wasm32 (feature-gate anything non-portable); root `Cargo.toml`.

**Interfaces (wasm-bindgen, JSON-in/JSON-out to keep the boundary simple):** `build_request(target_json, request_json) -> http_request_json` (`{method, url, headers, body}`), `parse_response(kind, status, body_bytes) -> response_json | throws error_json`, `StreamDecoder` class (`new(kind)`, `feed(bytes) -> events_json`, `finish() -> events_json`, `takeError() -> error_json|null`), `parse_embeddings(kind, status, body, model) -> json`, `build_embeddings_request(...)`, and gateway-format builders (OpenAI ingress) for the gateway target.

**Tests:** `cargo build -p ultrafast-client-wasm --target wasm32-unknown-unknown`; Rust unit tests of the JSON boundary on the host; `wasm-bindgen-test` or a Node smoke test calling the built module for one request/response and one stream. Install `rustup target add wasm32-unknown-unknown` and `wasm-bindgen-cli` (matching the wasm-bindgen crate version) user-level.

**Files:** Create `crates/client-py/{Cargo.toml,pyproject.toml,src/lib.rs,python/ultrafast/__init__.py,python/ultrafast/_types.py,tests/test_*.py,README.md}`; root `Cargo.toml`; `.github/workflows/clients.yml` (build wheels with maturin-action for linux/macos/windows × x86_64/aarch64 — config only, not run locally).

**Interfaces:** `ultrafast.Client(target)`, `ultrafast.AsyncClient(target)`; targets `ultrafast.gateway(base_url, key)`, `ultrafast.openai(key, base_url=None)`, `anthropic(key)`, `gemini(key)`, `azure(endpoint, key, api_version=None)`, `openai_compatible(base_url, key)`; `client.chat(model, messages, *, max_tokens=None, temperature=None, top_p=None, stop=None, tags=None) -> ChatResponse`; `client.chat_stream(...)` → iterator of events (`AsyncClient` → async iterator); `client.embed(model, input, *, dimensions=None, tags=None)`; `ultrafast.Error` with `.kind`, `.status`, `.retryable`, `.retry_after`, subclasses per kind; typed dataclass-like result objects with `__repr__` that never contains the key. The extension embeds a tokio runtime; the GIL is released during I/O.

**Tests:** pytest against a local mock server (Python `http.server` in a thread) for chat, stream, embed, errors, Review Focus 1–4; async tests with `asyncio`. Build with `maturin develop` in a venv (`python3 -m venv`, `pip install maturin pytest`); report if Python headers or anything needs sudo (PyO3 does not need Python.h on Linux).
