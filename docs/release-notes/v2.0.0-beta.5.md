# Ultrafast 2.0.0-beta.5

The fifth beta of Ultrafast v2: the MCP gateway core. Agents reach the tools of
registered MCP servers through the gateway, with a virtual key, under the same
access rules, limits, budgets and guardrails as model calls. It is still a
beta, so pin the version.

## Highlights

- **Register servers, sync tools.** Admins add an MCP server with a bearer or
  header credential (stored encrypted, never shown again) and sync its tools.
  Synced tools start off.
- **Access like a model.** Switch a tool on, grant it to everyone, teams or
  users, and optionally limit a key to `mcp:<server>/<tool>` entries.
- **One endpoint per server.** `POST /mcp/{server}` answers `initialize`,
  `ping`, `tools/list` and `tools/call`, statelessly. A key with nothing to
  call on a server is told the same 404 as for an unknown server.
- **The `/v1` pipeline.** Rate limits, budgets and guardrails apply to tool
  calls; calls are logged under the endpoint `mcp`, counted in metrics and
  exported as `mcp.call` spans.
- **Caps.** Call timeout, result, argument and discovery sizes are set by
  `UF_MCP_CALL_TIMEOUT`, `UF_MCP_MAX_RESULT_BYTES`, `UF_MCP_MAX_ARGS_BYTES`
  and `UF_MCP_MAX_DISCOVERY_BYTES`; 32 calls to one server run at once per
  process.
- **Console.** An MCP tools page, an MCP section on key creation and a logs
  filter.

The full list is in the [CHANGELOG](https://github.com/techgopal/ultrafast-ai-gateway/blob/v2.0.0-beta.5/CHANGELOG.md).

## Install

Archives on the release assets (check `SHA256SUMS`), or Docker (linux/amd64):

```bash
docker run -p 3000:3000 -v ultrafast-data:/var/lib/ultrafast \
  -e UF_ADMIN_EMAIL=you@example.com -e UF_ADMIN_PASSWORD='a long password' \
  ghcr.io/techgopal/ultrafast-ai-gateway:2.0.0-beta.5
```

The `latest` tag is for stable releases only; reach a beta by its version tag.

## Upgrading from beta.4

Back up first (the console's Backup panel, or copy the SQLite file with the
gateway stopped), then stop, replace the binary or image, start.

- A new migration runs automatically at start (SQLite 0021, PostgreSQL 0007).
  A database written by beta.4 opens as it is; there is no way back to beta.4
  once it has migrated, short of the backup.
- No MCP server exists after the upgrade, and no key reaches one until an
  admin registers it and grants tools.
- `docs/compose/postgres.yml` pins `2.0.0-beta.5`.

## Known limits

- Rate limits, the response cache, single-flight, breaker health and alert
  error windows are per process, also on PostgreSQL; budgets converge about
  every 5 s. A revocation reaches the other processes within about 30 s.
  The 32-call cap per MCP server is per process too.
- MCP: tools only (no resources or prompts), no OAuth to upstream servers, no
  stdio servers.
- One OIDC provider; no SAML or SCIM.
- Traces only (OTLP JSON over HTTP); alerts go to webhooks only.
- Guardrails do not inspect images or audio, and have no built-in classifiers.
- Registry publishing is a dry run until trusted publishers are registered;
  build the clients and SDKs from source until then.

The README's "Known limits" section has the details.
