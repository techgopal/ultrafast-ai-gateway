# Ultrafast 2.1.0

MCP at scale. The gateway you run for models now also runs a catalog of MCP servers,
supervises local ones, tells you when one is down, gives agents one endpoint for every
tool they may call (with search when there are hundreds), trims what tools answer, and
signs in to servers that need OAuth, without ever passing an agent's key on.

## Highlights

- **A signed catalog.** *Add from catalog* offers a curated list (GitHub, Linear, Sentry,
  Notion, Slack, Brave Search, Fetch, Filesystem, Postgres). It is signed with Ed25519,
  fetched and cached, with a copy in the binary. `UF_MCP_CATALOG=off` makes no request
  at all.
- **Local servers.** `UF_MCP_LOCAL=on` lets an admin run an MCP server as a program on
  the gateway host: exact argv, no shell, only the environment you list, a working
  directory of its own, restarts with backoff, its stderr kept. Never as root; never from
  a configuration file; supervised, not sandboxed.
- **Health.** Every server is asked for its tool list about every minute, outside the key
  pipeline. `uf_mcp_server_up{server}`, the console, and a new **MCP server down** alert.
- **One endpoint.** `POST /mcp` lists every tool a key may call as `server__tool`; the
  per-server endpoints are unchanged. The MCP tools page shows both addresses.
- **Many tools.** Past 40 tools a key gets `find_tools` (BM25) and `describe_tools` and
  its pinned tools instead of the whole list.
- **Projection.** Per tool, keep and drop JSONPath lists and size limits cut a result
  before the guardrails read it, with a preview.
- **OAuth toward servers.** Client credentials or token exchange, for the server's own
  address, cached and renewed once; the agent's key never leaves the gateway.
- **Also.** `resources/*` and `prompts/*` pass through `/mcp/{server}`; servers that need
  an `Mcp-Session-Id` work; a playground tab calls MCP tools as you; a server cannot be
  added at a private address unless `UF_MCP_ALLOW_PRIVATE_UPSTREAMS=on`.

The full list is in the [CHANGELOG](https://github.com/techgopal/ultrafast-ai-gateway/blob/v2.1.0/CHANGELOG.md).

## Install

Archives on the release assets (check `SHA256SUMS`), or Docker (linux/amd64):

```bash
docker run -p 3000:3000 -v ultrafast-data:/var/lib/ultrafast \
  -e UF_ADMIN_EMAIL=you@example.com -e UF_ADMIN_PASSWORD='a long password' \
  ghcr.io/techgopal/ultrafast-ai-gateway:2.1.0
```

## Upgrading from 2.0.0-beta.5

Back up first (the console's Backup panel, or copy the SQLite file with the gateway
stopped), then stop, replace the binary or image, start.

- Migrations run at start (SQLite 0022 to 0024, PostgreSQL 0008 to 0010). Migration 0022
  rebuilds the alert rules table (nothing in it changes). There is no way back to beta.5
  once a database has migrated, short of the backup.
- A server registered at a loopback, private or link-local address keeps working, but
  cannot be added or moved there again without `UF_MCP_ALLOW_PRIVATE_UPSTREAMS=on`.
- Nothing runs locally and no catalog is fetched until you want it; set
  `UF_MCP_CATALOG=off` to never fetch it.
- The release workflow signs the catalog with the repository secret
  `MCP_CATALOG_SIGNING_KEY`; see `docs/mcp-catalog/README.md` before tagging.

## Known limits

- Discovery is lexical, not semantic. OAuth is one client for each server, not per person.
- Local servers are supervised, not sandboxed.
- Health, cached tokens and the catalog's freshness are per process.
- Registry publishing is a dry run until trusted publishers are registered.
