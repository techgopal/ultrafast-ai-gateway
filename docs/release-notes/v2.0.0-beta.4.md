# Ultrafast 2.0.0-beta.4

The fourth beta of Ultrafast v2: a hardening release. Guardrails reach teams
and users, single sign-on users can get a password, a call no longer fails
because the first target cannot express it, and the clients are ready to be
published. It is still a beta, so pin the version.

## Highlights

- **Team and user guardrails.** Attach a guardrail to a team or a user, as you
  could to every call, a route or a key. They apply in this order: defaults,
  the caller's team, the teams its owner leads, the user, the route, the key.
  A personal key is covered by the teams of its owner.
- **Password links for single sign-on users.** An admin makes a single-use,
  24 hour link from the user's page; the user sets a password and keeps the
  identity link, role and sessions. A failed sign-in returns to the sign-in
  page with the page you were going to kept.
- **Skip to the fallback.** When a target cannot express a feature of the
  request (for example audio input), the gateway skips it and tries the next
  target. The call's attempts show it as `skipped`, with the reason
  `unsupported:<feature>`, in the API and in the console.
- **Alerts for team leads.** Leads read the alert rules and events of their
  teams. The alert heartbeat uses the database clock, so processes on a shared
  PostgreSQL no longer take over each other's alerts when their clocks differ.
- **Console branding.** The brand mark and name in the sidebar, the mobile
  header and the sign-in pages.
- **Publishing, as a dry run.** A tag workflow publishes the Rust, Python and
  TypeScript clients and the admin SDKs to crates.io, PyPI and npm, and does
  nothing real until the owner registers trusted publishers and sets
  `PUBLISH_LIVE`. This release publishes nothing.

The full list is in the [CHANGELOG](https://github.com/techgopal/ultrafast-ai-gateway/blob/v2.0.0-beta.4/CHANGELOG.md).

## Install

Archives on the release assets (check `SHA256SUMS`), or Docker (linux/amd64):

```bash
docker run -p 3000:3000 -v ultrafast-data:/var/lib/ultrafast \
  -e UF_ADMIN_EMAIL=you@example.com -e UF_ADMIN_PASSWORD='a long password' \
  ghcr.io/techgopal/ultrafast-ai-gateway:2.0.0-beta.4
```

The `latest` tag is for stable releases only; reach a beta by its version tag.

## Upgrading from beta.3

Back up first (the console's Backup panel, or copy the SQLite file with the
gateway stopped), then stop, replace the binary or image, start.

- New migrations run automatically at start (SQLite 0019 and 0020, PostgreSQL
  the matching ones). A database written by beta.3 opens as it is; there is no
  way back to beta.3 once it has migrated, short of the backup.
- Guardrails attached to teams and users start empty. Existing guardrails
  keep their place in the order.
- A call whose first target cannot express the request now goes to the next
  target instead of failing; if none can, the answer is as before.
- Team leads now see the alerts of their teams.
- `docs/compose/postgres.yml` pins `2.0.0-beta.4`.

## Known limits

- Rate limits, the response cache, single-flight, breaker health and alert
  error windows are per process, also on PostgreSQL; budgets converge about
  every 5 s. A revocation reaches the other processes within about 30 s.
- One OIDC provider; no SAML or SCIM.
- Traces only (OTLP JSON over HTTP); alerts go to webhooks only.
- Guardrails do not inspect images or audio, and have no built-in classifiers.
- The client libraries (Rust, Python, TypeScript) do not yet call
  `/v1/responses`, images, audio or prompt templates.
- Registry publishing is a dry run until trusted publishers are registered;
  build the clients and SDKs from source until then.

The README's "Known limits" section has the details.
