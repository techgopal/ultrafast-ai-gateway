# Ultrafast 2.0.0-beta.3

The third beta of Ultrafast v2, and the end of Phase 2: the gateway can be
watched (traces and alerts), signed into with your identity provider, run on
PostgreSQL, guarded, and called through more of the OpenAI surface; and it can
be managed from code. It is still a beta, so pin the version.

## Highlights

- **Tracing and alerts.** Every `/v1` call can be exported as an OpenTelemetry
  trace over OTLP/HTTP (`UF_OTEL_ENDPOINT`), one span per call and per provider
  attempt. Budget, error-rate and circuit-open alert rules tell signed webhook
  or Slack-compatible channels; a console page manages them.
- **Single sign-on.** One OpenID Connect provider (Google, Entra ID, Okta,
  Keycloak, any with discovery), with PKCE and ID token checks, linking by
  `<issuer>|<sub>` or verified email, and an optional admin group. Passwords
  keep working. Set `UF_PUBLIC_URL`.
- **PostgreSQL (optional).** `UF_DATABASE_URL` runs the gateway on PostgreSQL,
  so several processes can share a database. SQLite stays the default.
  `UF_MASTER_KEY` is required on PostgreSQL. Budgets are shared; rate limits,
  the cache and breaker health are per process (README, "Known limits").
- **Guardrails.** Block, redact or flag what goes to models and what comes
  back: keywords, regular expressions and PII detectors in the gateway, or a
  signed external webhook. Attach them to every call, a route or a key; streams
  are checked; the logs show what acted.
- **More of the API.** The Responses API (`/v1/responses`), structured outputs
  (`response_format` and `text.format`, and `output_config.format` on
  `/v1/messages`), image generation, audio transcription, translation and
  speech, and reasoning effort with `max_completion_tokens` for OpenAI and
  Azure. The playground has Images and Audio modes and a response format
  control.
- **Prompt templates.** Named, immutable versions with `{{variables}}`, used
  with a `prompt` object on chat completions and the Responses API; a console
  page with a version diff; included in configuration export and import.
- **Admin SDKs.** `@ultrafast/admin` (TypeScript) and `ultrafast-admin`
  (Python 3.11 or newer) for the admin API, generated from `openapi/admin.json`
  and checked against it in CI. Build from source; not published to npm or PyPI.

The full list is in the [CHANGELOG](https://github.com/techgopal/ultrafast-ai-gateway/blob/v2.0.0-beta.3/CHANGELOG.md).

## Install

Archives on the release assets (check `SHA256SUMS`), or Docker (linux/amd64):

```bash
docker run -p 3000:3000 -v ultrafast-data:/var/lib/ultrafast \
  -e UF_ADMIN_EMAIL=you@example.com -e UF_ADMIN_PASSWORD='a long password' \
  ghcr.io/techgopal/ultrafast-ai-gateway:2.0.0-beta.3
```

The `latest` tag is for stable releases only; reach a beta by its version tag.

## Upgrading from beta.2

Back up first (the console's Backup panel, or copy the SQLite file with the
gateway stopped), then stop, replace the binary or image, start.

- The new migrations (SQLite 0014 to 0018) run automatically at start. A
  database written by beta.2 opens as it is; there is no step to take, and no
  way back to beta.2 once it has migrated, short of the backup.
- PostgreSQL is optional. A gateway that sets nothing keeps using SQLite.
  There is no online migration from SQLite to PostgreSQL; a configuration
  export and import moves the setup, not the logs or the keys' usage.
- Single sign-on, tracing, alerts and guardrails are off until you configure
  them.
- `docs/compose/postgres.yml` pins `2.0.0-beta.3`; the first release that can
  use PostgreSQL is this one, and an older gateway ignores `UF_DATABASE_URL`.
- OpenAI (`api.openai.com`) and Azure targets are now sent
  `max_completion_tokens` instead of `max_tokens`, which the o-series and GPT-5
  models require. Other OpenAI-compatible hosts keep `max_tokens`.
- Multiple Anthropic `system` blocks are joined with a newline (they were
  joined with nothing).
- Alert history is deleted with the request logs, after the log retention
  period; before, it was kept for ever.
- A JSON schema sent as `output_config.format` on `/v1/messages` goes to OpenAI
  and Azure as `strict: true`, which they accept only for a schema with
  `additionalProperties: false` on every object and all properties in
  `required`.

## Known limits

- Rate limits, the response cache, single-flight, breaker health and alert
  error windows are per process, also on PostgreSQL; budgets converge about
  every 5 s. A revocation reaches the other processes within about 30 s.
- One OIDC provider; no SAML or SCIM.
- Traces only (OTLP JSON over HTTP); alerts go to webhooks only.
- Guardrails do not inspect images or audio, and have no built-in classifiers.
- The client libraries (Rust, Python, TypeScript) do not yet call
  `/v1/responses`, images, audio or prompt templates.
- Wheels, the npm packages, the admin SDKs and the crates are not published.

The README's "Known limits" section has the details.
